# SOUL — the logic gate your agent runs on (sample)

An agent has to know what it is *supposed* to do and what it is *not* supposed to
do. This kit hands it that as a **narrative logic gate** — a governing framework it
stands on and runs against, not brute-force prompting or a pile of literature fed
in hopefully.

**The canonical framework (ours, public, kept current, attributed):**
👉 https://shannondobbs.com/regenerative-gem/

That's the Regenerative Gem — a coordination pattern library that works as the
agent's do / don't logic: load it and the agent learns which moves create cascade
and which don't, and how to position as a vendor solving a problem rather than a
supplicant asking for support. It is served as a **living HTML page** — navigable
by an agent, readable by a human, always current. Point the SOUL at the URL so the
canonical version stays authoritative and updates propagate to every agent standing
on it. The Gem is built to run **functional on your own sovereign iron** — your box,
your rules, the framework live behind your agent.

The operator discipline that comes with running this — the range rules — lives in
**WHY.md**. Read it before you wire anything live.

*Why this is safe to share:* an agent's sovereignty does not live in its SOUL —
which is exactly why the SOUL is shareable. Sovereignty lives one layer down, in the
**plumbing**: which tools are wired behind the agent (the hands) and what each call
is allowed to see (the eyes / RLS). Share the framework freely; the control stays in
the wiring.
